> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Formats et qualité au choix (MP4/MKV/MOV, MP3/M4A/Opus/FLAC/WAV, H.264 par défaut, extrait, métadonnées retirées), sites mieux pris en charge (Instagram/TikTok, Bilibili, posts X multi-vidéos), stockage court et borné, reprise d'un téléchargement annulé, historique de 30 jours, page `/admin` avec comptes email + mot de passe, et frontend React + shadcn/ui identique aux maquettes.

## Global Constraints

- Aucun fichier source au-delà de ~300 lignes.
- Types d'API uniquement dans `crates/shared` ; `web/src/api/types.gen.ts` régénéré (`UPDATE_TS=1 cargo test -p reclip-shared --test export_ts`), jamais édité à la main.
- Défauts : `RECLIP_FILE_TTL=21600` (6 h), `RECLIP_MAX_DISK=5G` (octets ; suffixes K/M/G acceptés), `RECLIP_CONCURRENT_FRAGMENTS=4`, `RECLIP_IMPERSONATE=chrome` (vide = désactivé), historique 30 jours, session admin 12 h, mot de passe admin ≥ 12 caractères.
- H.264 + AAC préférés par défaut ; une hauteur sans H.264 est proposée avec l'étiquette du codec (« 2160p VP9 »).
- CSP stricte conservée : `script-src 'self'` ; `style-src 'self' 'nonce-<n>' https://fonts.googleapis.com` sur les pages HTML (nonce par réponse), aucun `'unsafe-inline'`.
- Apparence = maquettes, au pixel près pour couleurs, polices (DM Mono, Instrument Serif), rayons, espacements ; mobile ≤ 560 px et tablette ≤ 900 px suivent les maquettes `*Mobile` / `*Tablet` (mise en page dédiée, cibles tactiles ≥ 44 px, aucun retour à la ligne forcé).
- Contrôles interactifs = composants shadcn/ui (Checkbox, Select, DropdownMenu, Tooltip, Dialog, Sheet, ToggleGroup), jamais `<select>` ni `<input type=checkbox>` natifs.
- Interface en anglais uniquement.
- Ne jamais lire, afficher, modifier ni committer `deploy/.env`.

### Task B1: Formats, qualité et sites (yt-dlp)

**Files:** `crates/core/src/ytdlp/{args,parse,runner,errors}.rs` uniquement (+ tests dans ces fichiers ou `ytdlp/tests_*.rs`).

- Vidéo : `-f "<id>+bestaudio[ext=m4a]/<id>+bestaudio/<id>/best"` avec un id, sinon `"bv*[vcodec^=avc1]+ba[ext=m4a]/bv*+ba/b"` ; `--merge-output-format mp4|mkv|mov` ; MP4 et MOV : `-movflags +faststart` via `--postprocessor-args "Merger+ffmpeg_o:-movflags +faststart"`.
- Audio : `-x --audio-format mp3|m4a|opus|flac|wav`.
- Extrait : `--download-sections "*<start>-<end|inf>"` (secondes).
- Métadonnées retirées : `-map_metadata -1` ajouté aux arguments ffmpeg de sortie (combiné avec faststart).
- `-N <concurrent_fragments>` ; `--impersonate <cible>` seulement pour les hôtes instagram.com, tiktok.com (et sous-domaines) quand `impersonate` est défini.
- Bilibili (bilibili.com, b23.tv) : `--add-headers "Origin:https://www.bilibili.com" --add-headers "Referer:https://www.bilibili.com/"`.
- `playlist_item` : `--playlist-items <n>` au lieu de `--no-playlist`.
- Miniature : `--write-thumbnail --convert-thumbnails jpg -o "thumbnail:<out_dir>/thumb.%(ext)s" --postprocessor-args "ThumbnailsConvertor+ffmpeg_o:-vf scale=160:-2"` (B2 la déplace après succès).

Un format sans `vcodec` mais avec `height` est vidéo (correctif Bilibili). Posts X/Twitter multi-vidéos : `PlaylistInfo` avec une entrée par vidéo (`url` du post, `playlist_item` 1..n, `title`).

### Task B2: Stockage borné, reprise et historique

**Files:** `crates/core/src/jobs/{mod,worker,cleanup,recovery,sched}.rs`, nouveau `jobs/disk.rs`, `crates/core/src/store/{queries,history}.rs`, `crates/core/src/http/{history,jobs}.rs` (handlers `resume`, historique), tests `crates/core/tests/history.rs`.

- Annuler garde le dossier de la tâche (fichiers `.part`) ; `Remove` le supprime ; l'expiration le supprime.
- `POST /jobs/{id}/resume` : tâche du demandeur `resumable` → repasse `queued` avec les mêmes options (yt-dlp reprend les `.part`) ; sinon 409 `invalid_request` « This download cannot be resumed ». Soumis aux mêmes quotas que la création.
- Fin de tâche réussie : média = le fichier qui n'est ni `thumb.jpg` ni `*.part` ; `thumb.jpg` déplacé vers `<data_dir>/thumbs/<id>.jpg` et `thumb_path` enregistré.
- Plafond disque (`jobs/disk.rs`) : taille de `downloads_dir` recalculée après chaque tâche et à chaque nettoyage ; avant de lancer une tâche, si la taille dépasse `max_disk`, expirer d'abord les fichiers partiels des tâches annulées les plus anciennes, puis les fichiers terminés les plus anciens ; si cela ne suffit pas, la tâche reste en file et le planificateur réessaie à la fin d'une tâche ou au nettoyage suivant.
- Historique : tâches `done` ou `expired` du propriétaire, non masquées (`hidden_at` NULL), créées depuis `history_days` ; `file_available` = `done` et fichier présent. `DELETE /history/{id}` masque ; `POST /history/clean` : `expired` masque les entrées dont le fichier a expiré, `older_than` masque celles de plus de `days` jours, `all` masque tout ; renvoie le nombre. `GET /history/{id}/thumb` sert la miniature (`image/jpeg`, `Cache-Control: private, max-age=86400`) ou 404.
- Purge : lignes `expired` et masquées supprimées après `history_days` (au lieu de 7 jours), miniature comprise.
- Tests : `resume_continues_partial` (le faux yt-dlp doit voir le `.part` existant ; étendre `fake-ytdlp` si nécessaire pour écrire puis reprendre un `.part`), `cancel_keeps_partial_remove_deletes`, `disk_cap_evicts_then_waits`, `history_lists_hides_and_cleans`, `thumb_served_and_purged`.
- Commit `feat(core): disk cap, resumable downloads and history`.
